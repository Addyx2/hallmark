Hallmark

When an agent acts, you need to know who authorised it.

Agents send email, spend API budget, write to workspaces and move money. When something goes wrong, a platform still has to answer one question: which human is responsible?

Hallmark gives the agent a passport that resolves to that human. It carries a signed lineage, a grant naming the action, and a short lifetime. The gateway checks it before the action runs.

The protocol and reference code are open. Read the specification if you want the exact rules.

Components

The pieces that make the trail usable.

A passport carries the lineage. A grant names the action and its budget. A receipt records the result. You can use each piece on its own.

Imprint

A signed lineage from agent to root attestation, bound to a human’s passkey.

Grants

Capability, budget, action, lifetime and jti in one token. Budgets split at spawn.

Barricade

A provider-side check at the surface where the action happens. It requires an imprint and a grant. This is where a client can refuse suspicious use.

Freeroam

Clients can add Freeroam to their own platform, see when agents use their site, and analyse the traffic. It observes cooperative agents, flags anomalies, and never denies.

Trackline

A receipt for each action: what ran, what it cost, and which grant allowed it.

Seal v2

Ownership seals on original work, so use can be licensed instead of copied.

Deployment

Put the check where the traffic is.

Verification is stateless. The passport carries no PII — only a lineage, a grant reference and public key material. Check it in the gateway, at the edge, or inside your VPC.

Gateway

One header check before routing. Reject, challenge, or allow with attribution, per route.

Edge

Stateless verification plus registry lookups, with no call back to a control plane.

VPC

Run the verifier and the registry anchor yourself. The format does not care where it is checked.

Security

Unknown input fails closed.

The passport is the only thing crossing the trust boundary. It is small and canonical, and anything unverifiable is rejected at the check.

Signatures are pinned. Only EdDSA and ES256 are accepted.

JSON is canonical. RFC 8785; duplicate keys and non-canonical encodings fail.

Keys come from the registry. No URL discovery.

Replay is rejected. A jti cache and sequence window stop reuse.

Revocation is per capability. Stale data fails closed for that capability.

Lifetimes are short. 120 seconds by default, 300 maximum.

Verify

Check a seal in the browser.

This verifier signs a sample passport, computes the seal, then checks both. Tamper with the subject and the chain fails. Nothing leaves the page.

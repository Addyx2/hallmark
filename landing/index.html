The problem

Intelligence is no longer the constraint. Attribution is.

Agents hold emails, burn API spend, write to workspaces and move money — and platforms still cannot answer the only question that matters when something goes wrong: which paying human is responsible for this action?

Blocking agents loses usage. Accepting them blind loses attribution and creates liability. The missing layer is not another detector or a better bot fingerprint — it is identity that resolves to a human, authorization that names the exact action, and provenance that survives the session.

Pascaal is that layer. Built on the open Hallmark protocol: Ed25519 with an ES256 fallback, RFC 8785 canonical JSON, short-lived passes, and budgets that are split — never shared — at spawn.

What we do

Six products. One loop.

Identity that resolves. Authorization that names the action. Provenance you can show a user. Each product is useful alone; together they close the loop from first contact to a receipt.

01

Imprint — identity that resolves

A passport is a signed lineage from agent → parent → … → root attestation, bound to a human’s passkey. Verification is stateless and measured in microseconds.

02

Grants — authorization that names the action

Capability, budget slice, action, lifetime and jti in one token. Route auth succeeds only when a capability matches; budgets are disjoint at spawn, charged on observed usage.

03

Barricade — enforcement at the platform

Provider-side plugin that requires an imprint and a grant per surface. Enroll users at their first responsibility, not their first contact.

04

Freeroam — observation with zero friction

Cooperative agents self-identify; you get attribution before you require anything. Observe-only, no accounts, no interception — the wedge to enforcement.

05

Trackline — provenance users can read

Every action becomes a receipt: what the agent did, what it cost, which grant authorized it, and how much budget remains.

06

Seal v2 — ownership of original work

Ownership seals on original works (hallmark+work), enabling licensed use and payment instead of silent copying.

Security

Designed to fail closed.

The passport is the only thing crossing the trust boundary, so it is small, canonical, and boring on purpose. Everything that could be abused is either forbidden by the format or pinned by the registry.

Algorithm allowlist. [EdDSA, ES256] — nothing else is accepted, ever.
Canonical JSON only. RFC 8785 JCS; duplicate keys and non-canonical encodings are rejected.
No key discovery by URL. jku, x5u and x5c are forbidden; keys come from the registry.
Replay suppressed. A jti cache plus a sequence window; reuse is a hard error, not a warning.
Revocation is per capability. Stale revocation data fails closed for that capability only.
Short lifetimes by construction. TTL ≤ 120 s, hard cap 300 s — the containment window is a design constant, not a policy promise.
Deployment

Pascaal runs where your traffic runs.

Verification is stateless and the passport carries no PII — only a lineage, a grant reference and public key material. Put it in front of the thing that already sees agent traffic.

001

In your gateway

One header check before routing. Reject, challenge, or allow with attribution — your call per route.

002

At the edge

Stateless verification plus registry lookups; no per-request call back to a control plane.

003

In your VPC

Self-host the verifier and the registry anchor. The passport format does not care where it is checked.
